# 2026-10-07 작업 기록

## 식단별 익명 채팅

- 날짜와 식단 ID별로 채팅방을 구분하고 식단 카드에 입장 버튼을 추가했다.
- 입장 버튼은 기존 별점 영역 오른쪽의 채팅 아이콘으로 배치하고, 별도의 버튼 행을 없앴다.
- 카드 본문을 세로 flex로 구성해 별점·채팅 영역을 하단에 정렬하고 높이를 56px로 통일했다. 메뉴 설명 길이에 관계없이 같은 행의 하단 구분선과 버튼 위치가 맞춰진다.
- 칼로리 표기는 디자인 변경을 검토한 뒤 최초의 주황색 둥근 배지(`총 칼로리 · 수치`)로 되돌렸다.
- 음식 이름 200개에서 서로 다른 두 개를 무작위로 조합해 중복 없는 익명 이름을 부여한다.
- 서버가 발급한 HttpOnly 쿠키로 사용자를 구분하며 이름과 메시지를 PostgreSQL에 보관한다.
- 모든 방을 합산해 사용자당 5초에 1개, 한국 시간 기준 하루 50개로 전송을 제한한다.
- 사용자 행 잠금과 트랜잭션으로 여러 탭·서버 인스턴스의 동시 요청에도 같은 제한을 적용한다.
- 채팅방은 3초마다 갱신하며 남은 일일 횟수, 전송 대기 시간, 이전 대화 조회를 제공한다.
- `V2__meal_chat.sql` 마이그레이션과 운영 DB와 분리된 Docker 통합 테스트 환경을 추가했다.

## 검증

- React 프로덕션 빌드와 Java 21 서버 패키징을 완료했다.
- 기존 테스트 14개와 채팅 PostgreSQL·HTTP 통합 테스트 9개가 통과했다.
- 5초 경계, 50개 제한, 한국 시간 자정 초기화, 자정을 넘는 전송 간격을 확인했다.
- 동시 전송 12건 중 1건만 저장되는 것과 사용자 구분·쿠키·요청 검증·이전 기록 조회를 확인했다.

## 오늘 식단 사진 갱신

- 분짜의 실제 사진은 서버에 저장됐지만, 준비 완료 식단 응답의 12시간 브라우저 캐시와 조회 중단 때문에 이전 화면이 남을 수 있었다.
- 오늘·미래 식단 응답에 `no-store`를 적용하고, 프론트 식단 조회에서도 기존 브라우저 캐시를 사용하지 않는다.
- 오늘 식단은 준비 완료 후에도 1분마다 다시 조회하며 네트워크 오류가 발생해도 자동 조회를 재시도한다.
- 별도의 사진 새로고침 버튼 없이 자동으로 최신 식단 응답을 조회하며 재조회 중에는 기존 카드를 유지한다.
- 다른 탭에서 돌아오거나 브라우저 뒤로 가기로 화면을 복원할 때 즉시 재조회한다. 숨겨진 탭은 주기 조회를 쉬고, 중복 요청은 방지한다.
- 갱신된 사진은 이미지 URL의 내용 해시가 달라져 이전 이미지 캐시를 자동으로 대체한다. 사용자에게 강력 새로고침을 요구하지 않는다.
- 프론트·서버 빌드와 기존 테스트 14개를 확인한 뒤 실행 중인 웹 컨테이너에 반영했다.
- 운영 API의 오늘 식단 응답이 `no-store`이고 분짜 실제 사진이 HTTP 200으로 제공되는 것을 확인했다.

## 적용

운영 반영은 `docker compose up -d --build`로 진행한다. 서버 기동 시 Flyway가 채팅 테이블을 생성한다.
사용자 구분은 브라우저 쿠키와 별도의 localStorage 식별키를 함께 사용한다. 쿠키만 삭제하면 사용자와 제한을 복원하며, 다른 브라우저·시크릿 창·사이트 데이터 전체 삭제는 새 사용자로 처리된다.

## 지난 메뉴 검색·참고 사진·오늘의 투표

- 저장된 과거 식단의 메뉴 이름·설명 검색과 전체 이름 일치 옵션, 24개 단위 더 보기, 사진 확대, 해당 날짜 식단 이동을 추가했다.
- 사진이 없는 메뉴에는 공백과 대소문자를 제외한 이름이 같은 과거 메뉴의 실제 사진을 제공한다. 최신 과거 사진부터 선택하며 참고 사진의 날짜를 표시하고, 해당 날짜 사진이 도착하면 자동으로 교체한다.
- 오늘 식단 투표는 익명 사용자당 한 표로 제한하며 선택 변경과 취소를 지원한다. 서버에서도 한국 시간 기준 오늘만 허용하고 사용자 행 잠금과 기본키로 동시 요청을 처리한다.
- 푸터에 Buy Me a Coffee 준비 중 버튼을 추가했다. URL은 연결하지 않았다.
- V3 마이그레이션은 사용자·날짜별 메뉴 선택 테이블을 추가한다.

## 쿠키 외 사용자 구분

- 브라우저에서 암호학적 난수 256비트 식별키를 만들어 localStorage에 저장한다. 서버에는 SHA-256 해시만 저장한다.
- 식별키를 기존 익명 사용자에 연결하고, 쿠키가 사라져도 같은 익명 이름·남은 채팅 횟수·투표를 복원한다. 기존 쿠키는 다음 접속 때 자동 연결된다.
- 키별 PostgreSQL 트랜잭션 잠금으로 여러 탭에서 동시에 최초 접속해도 사용자 하나만 생성한다.
- V4 마이그레이션은 식별키 해시와 익명 사용자 연결을 추가한다. MAC 주소와 IP 기반 식별은 사용하지 않는다.
- 로그인 없는 브라우저 식별이므로 사이트 데이터 전체 삭제나 다른 브라우저까지 동일인으로 판별할 수는 없다.

## 추가 검증과 반영

- 실제 PostgreSQL·HTTP 통합 테스트 18개가 통과했다. 검색 조건·페이지 나누기·과거 사진 선별·투표 변경/취소/동시 요청·브라우저 식별키 복원을 확인했다.
- Chromium에서 데스크톱과 모바일 화면, 검색, 투표 선택/취소, 후원 버튼 비활성 상태, 쿠키 삭제 후 브라우저 식별키 유지와 JavaScript 오류 여부를 확인했다. 투표와 식별 API는 브라우저 검증에서 모의 응답으로 대체해 운영 데이터에 테스트 투표를 남기지 않았다.
- 웹 컨테이너에 반영하고 V3·V4 마이그레이션, 상태 확인과 검색·투표 조회 API HTTP 200 응답을 확인했다.

## 요청에 따른 기능 정리

- 투표 화면·클라이언트 조회·서버 API와 지난 메뉴 검색 화면·검색 API를 제거했다. 사진 없는 카드의 지난 기록 검색 버튼도 제거했다.
- 같은 이름의 과거 사진을 자동 표시하는 기능과 날짜 표시, 사진 확대, 실제 사진 도착 시 자동 교체만 남겼다.
- 참고 사진 조회는 별점·설명 검색 없이 동일 메뉴 이름과 실제 이미지 파일만 확인하도록 단순화했다.
- 이미 운영에 적용된 V3 마이그레이션은 변경하지 않고 V5에서 더 이상 사용하지 않는 투표 테이블을 삭제한다.
- 기존 테스트 14개와 PostgreSQL·HTTP 통합 테스트 13개가 통과했다. Chromium에서 검색·투표 화면과 투표 조회 요청 제거, 참고 사진 날짜·확대·실제 사진 자동 교체와 모바일 레이아웃을 확인했다.
- 서비스에 반영한 뒤 삭제된 검색·투표 API의 HTTP 404, 참고 사진 API의 HTTP 200과 서버 정상 상태를 확인했다.

## 참고 사진용 메뉴 이름 정규화

- 비교할 때 대괄호 태그, 공백(일반·전각·줄바꿈 등), 기호를 제거하고 대소문자·전각 문자 차이를 정리한다. 화면에 표시하는 원래 메뉴 이름은 유지한다.
- 이차돌 등 메뉴 이름에 포함된 브랜드·식당명은 유지한다. 정규화 후 전체 이름이 완전히 같아야 연결하며 이차돌된장찌개와 된장찌개는 별개 메뉴로 처리한다.
- 음식 종류·재료·괄호 안의 글자는 유지한다. 이름 전체가 대괄호인 라면 선택 메뉴는 태그로 삭제하지 않으며 정규화 결과가 빈 문자열이면 참고 사진을 연결하지 않는다.
- V6 PostgreSQL 함수 하나를 현재·과거 메뉴 양쪽에 적용해 같은 규칙으로 비교한다. 띄어쓰기·태그·기호 차이는 연결하고 이차돌된장찌개/된장찌개 및 김치찌개/참치김치찌개처럼 이름이 다른 메뉴는 구분하는 통합 테스트를 추가했다.
- 기존 테스트 14개와 PostgreSQL·HTTP 통합 테스트 14개가 통과했다.

## 플로팅 투표 재추가

- 본문 위의 큰 영역 대신 우측 하단 아이콘으로 투표창을 연다. 오늘 식단이 있을 때만 표시하고 사진 확대·채팅 중에는 숨긴다.
- 작은 창에서 메뉴 선택·변경·취소, 참여 인원·비율과 남은 횟수·5초 대기 시간을 제공한다. 창이 열린 동안만 집계를 조회한다.
- 사용자별 5초에 1회, 한국 시간 기준 하루 10회 제한을 서버에서 적용한다. 선택·변경·취소는 각각 1회 사용하며 동일 선택을 재전송해도 추가 차감하지 않는다. 채팅 제한과는 별도로 관리한다.
- 사용자 행 잠금으로 동시 요청에도 한 번만 저장하며 쿠키만 삭제하면 기존 브라우저 식별키로 사용자·남은 횟수를 복원한다.
- V7에서 투표 테이블과 사용자별 제한 테이블을 생성한다. 기존 V5의 삭제 기록은 그대로 보존한다.
- 기존 테스트 14개와 PostgreSQL·HTTP 통합 테스트 18개가 통과했다. 5초 제한, 하루 10회, 자정 초기화와 전송 간격 유지, 동시 요청, 변경·취소·재전송과 쿠키 복원을 확인했다.
- 운영 컨테이너에 반영하고 정상 상태와 투표 조회 API를 확인했다. Chromium에서 PC·모바일 플로팅 위치, 선택·취소·대기 시간·횟수 소진, 닫기·과거 날짜에서 숨기기를 확인했다. 브라우저의 투표·익명 사용자 API는 모의 응답으로 대체했다.

## 푸터 배치·플로팅 커피·중앙 투표 모달

- 후원 버튼을 푸터 기존 안내 내용의 오른쪽으로 옮기고 별도 하단 행과 문구를 제거했다. 모바일에서는 짧은 커피 후원 문구를 표시한다.
- 우측 하단 투표 아이콘 왼쪽에 노란색 커피 아이콘을 추가했다. 과거 날짜나 식단 없는 화면에서도 후원 링크를 제공한다.
- 푸터와 플로팅 후원 링크는 공통 컴포넌트를 사용한다.
- 투표창은 화면 중앙의 native dialog 모달로 변경했다. 배경 클릭·Escape·닫기 버튼, 배경 스크롤 잠금과 키보드 포커스 제한을 제공한다.
- 추가 요청에 따라 모달 높이를 화면 전체 높이(상하 여백 제외)로 늘리고 내부 스크롤을 제거했다. 메뉴 행이 남은 높이를 나눠 사용하고 낮은 화면에서는 두 열로 배치한다. 투표 아이콘은 체크 표시가 있는 투표함으로 교체했다.
- 빌드 후 서비스에 반영했다. Chromium에서 PC·모바일 푸터 오른쪽 배치와 높이, 플로팅 아이콘 간격·링크, 중앙 모달 위치·높이, 작은 화면의 전체 메뉴 표시, 키보드 포커스·Escape·배경 닫기와 스크롤 잠금을 확인했다.
