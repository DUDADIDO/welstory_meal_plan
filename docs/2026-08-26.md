# 2026-08-26 작업 기록

## 목표

기존 Mattermost 봇으로 제공하던 삼성 웰스토리 삼성전기 부산사업장 중식 식단을 일반 사용자가 빠르게 확인할 수 있는 웹사이트로 전환했다.

주요 요구사항은 다음과 같았다.

- React 기반 웹 UI
- `DESIGN-apple.md`를 참고한 Apple 스타일 디자인
- 웰스토리 자격증명을 브라우저에 노출하지 않는 서버 구조
- 식단 업로드 시간이 일정하지 않은 상황을 고려한 주기적 확인
- 사진이 확보된 식단에 대한 웰스토리 재요청 방지
- 다수 방문자가 접속해도 느려지지 않는 캐시 및 동시성 처리
- Java 21, Spring Boot 기반 백엔드
- 홈 서버에 배포할 수 있는 Docker 구성

## 아키텍처

프로덕션에서는 하나의 Spring Boot 컨테이너가 API와 React 정적 파일을 함께 제공한다.

```text
Browser
  ├─ GET /                     React 정적 화면
  ├─ GET /api/meals            날짜별 식단 JSON
  └─ GET /api/meals/.../images 서버에 저장된 식단 이미지
              │
              ▼
       Spring Boot / Java 21
          ├─ 메모리 캐시
          ├─ 날짜별 디스크 캐시
          ├─ 요청 병합 잠금
          └─ Welstory Plus API
```

개발 환경에서는 Vite가 `/api` 요청을 `localhost:8080`으로 프록시한다.

## 백엔드

Spring Boot `3.5.9`와 Java 21을 사용했다.

### 웰스토리 연동

`WelstoryApiClient`가 레거시 `welstory-api-wrapper`의 실제 요청 규격을 Java로 옮긴다.

- 로그인: `POST /login`
- 요청 헤더: `User-Agent: Welplus`, `X-Device-Id`, `Authorization`
- 식단: `GET /api/meal`
- 로그인 토큰은 메모리에서 25분 동안 재사용
- 인증 만료 응답을 받으면 한 번 다시 로그인
- 연결 제한 시간 5초, 읽기 제한 시간 15초

### 캐시 정책

캐시는 `WELSTORY_CACHE_DIR/YYYY-MM-DD` 아래에 저장한다.

- `cache.json`: 메뉴 및 캐시 상태
- `meal-01.jpg` 등의 파일: 웰스토리에서 내려받은 사진
- 파일은 임시 파일에 먼저 쓴 뒤 원자적으로 교체
- 동일 날짜 새로고침은 `ReentrantLock`으로 한 번만 실행
- 평상시 재시도 간격 5분
- 정기 시간 외 사용자 요청에 대한 재시도 간격 30분
- 사진 URL이 바뀌면 기존 임시 이미지를 재사용하지 않음

모든 메뉴 사진이 저장되면 해당 날짜를 `complete=true`로 봉인한다. 완성된 날짜는 서버 재시작 후에도 디스크에서 바로 복원하며 웰스토리 API를 다시 호출하지 않는다.

완성 전 이미지는 외부에 노출하지 않는다. 완성 후 이미지 URL은 내용이 변하지 않으므로 30일 `immutable` 캐시 헤더를 사용한다. 완성 식단 JSON은 12시간 동안 공개 캐시할 수 있다.

### 스케줄

한국 시간 기준 평일 06:00부터 10:40까지 5분 간격으로 확인한다.

- 토요일과 일요일은 조회하지 않음
- `WELSTORY_HOLIDAYS`로 지정한 휴무일은 조회하지 않음
- 이미 완성된 날짜는 스케줄이 실행돼도 원격 요청 없이 즉시 종료

### API

| API | 설명 |
|---|---|
| `GET /api/meals` | 한국 시간 기준 오늘의 식단 |
| `GET /api/meals?date=YYYY-MM-DD` | 지정 날짜 식단 |
| `GET /api/meals/{date}/images/{mealId}` | 완성 후 서버에 캐시된 이미지 |
| `GET /actuator/health` | 컨테이너 상태 확인 |

식단 상태는 `READY`, `WAITING`, `UNAVAILABLE`, `ERROR`로 구분한다.

## Docker 및 운영

멀티 스테이지 Dockerfile을 구성했다.

1. Node 22에서 React 빌드
2. Maven 3.9 + Java 21에서 테스트 및 Spring Boot jar 빌드
3. Java 21 JRE Alpine 이미지에 실행 파일만 복사

운영 컨테이너는 다음 제한을 적용한다.

- 비루트 `app` 사용자
- 읽기 전용 루트 파일시스템
- `/tmp`만 tmpfs 사용
- `/data/cache` Docker 볼륨으로 캐시 영속화
- `no-new-privileges`
- Actuator 기반 Docker healthcheck
- `unless-stopped` 재시작 정책

배포 방법은 루트 `README.md`와 `.env.example`에 정리했다.

## 확인이 필요한 사항

개발 환경에 실제 웰스토리 계정이 제공되지 않아 운영 계정 로그인과 당일 실데이터 호출은 수행하지 않았다. 로그인 헤더, 요청 URL, 쿼리, 응답 필드는 설치된 레거시 `welstory-api-wrapper@0.1.4` 패키지의 구현을 직접 확인해 이식했다.

배포 전 `.env`에 다음 값을 입력해야 한다.

```dotenv
WELSTORY_USERNAME=...
WELSTORY_PASSWORD=...
```

실데이터 첫 확인 시 메뉴 코스명과 사진이 정상적으로 매핑되는지만 운영 로그와 화면에서 확인하면 된다.

## UI 개선

초기 식단 타일의 이미지가 화면을 지나치게 크게 차지한다는 피드백을 반영해 Apple Store의 utility card 문법에 가깝게 다시 구성했다.

- 반 화면 크기의 2열 타일과 거대한 선택 개수 장식 제거
- 콘텐츠 최대 폭을 1180px로 제한
- 데스크톱 3열, 태블릿 2열, 모바일 1열 카드 구성
- 식단 이미지 높이를 데스크톱 238px, 모바일 230px로 제한
- 카드에는 그림자를 제거하고 18px radius와 1px hairline만 사용
- 메뉴 제목을 24px로 낮추고 코스명, 번호, 반찬 설명의 정보 위계 정리
- Hero 높이를 350px로 줄이고 중앙 정렬된 한 줄 제목으로 단순화

날짜 이동 버튼 사이에 커스텀 캘린더 팝오버를 추가했다.

- 현재 선택 날짜와 오늘을 각각 표시
- 이전/다음 달 이동
- 미래 날짜 선택 차단
- 날짜 선택 후 자동 닫기
- 외부 클릭과 `Escape` 키로 닫기
- 과거 날짜 선택 시 오늘로 돌아가기 제공
- 모바일에서는 화면 좌우 16px 안에 맞는 고정형 팝오버로 전환

실제 웰스토리 당일 메뉴 6개와 캐시 이미지를 사용해 데스크톱 3열 카드, 모바일 1열 카드, 캘린더 팝오버를 검수했다. 브라우저 콘솔 오류가 없고 375px 화면에서 가로 오버플로가 발생하지 않음을 확인했다.

## 프런트엔드 구조 개선 및 운영 기능

단일 `App.jsx`에 모여 있던 화면과 상태 로직을 React Router 7 및 Tailwind CSS 4 기반으로 재구성했다.

```text
frontend/src
├─ assets/       아이콘과 Tailwind 전역 진입점
├─ components/   admin, calendar, common, meal, navigation 도메인 UI
├─ hooks/        식단·별점·운영 상태 로직
├─ layouts/      일반/운영 화면 공통 골격
├─ pages/        Main, Admin, NotFound 라우트 화면
├─ router/       createBrowserRouter 라우트 정의
├─ services/     HTTP API 클라이언트
└─ utils/        날짜와 표시 형식 유틸리티
```

- `App.jsx`는 `RouterProvider`만 렌더링한다.
- `/`와 `/admin`은 각각 레이아웃과 index route를 사용한다.
- 기존 대형 `styles.css`를 제거했다.
- 전역 CSS에는 Tailwind import, 디자인 토큰, 최소 base rule만 둔다.
- 카드, 캘린더, 확대 모달, 운영 콘솔 스타일은 컴포넌트의 Tailwind utility class로 관리한다.
- API 호출을 `services/http.js`로 모아 화면 컴포넌트에서 통신 세부 구현을 분리했다.

추가 기능은 다음과 같다.

- 식단 사진 클릭 시 확대 모달, 배경 클릭 및 Escape 닫기
- 브라우저별 식단 1~5점 평가와 날짜별 영속 저장
- 웰스토리의 `준비 중입니다` 이미지를 색상 분포와 이미지 해시로 판별
- 준비 중/중복/누락 이미지는 캐시 완료로 봉인하지 않고 계속 재확인
- `/admin`에서 날짜별 캐시, 실제·준비 중·누락 이미지, 용량, 별점 통계 확인
- `.env`의 `ADMIN_USERNAME`, `ADMIN_PASSWORD`와 Spring Security HTTP Basic 인증

검증 결과는 Vite 프로덕션 빌드 성공, Docker 멀티 스테이지 빌드 성공, Java 테스트 4개 통과다. 사용자 요청에 따라 이번 구조 개선에서는 브라우저 렌더링 검사를 수행하지 않았다.

### 부분 이미지 공개 수정

메뉴 6개 중 일부만 실제 사진으로 교체된 경우에도 날짜 전체 캐시가 완료될 때까지 정상 사진까지 숨겨지는 문제를 수정했다. 이제 실제 사진으로 판별된 메뉴는 즉시 이미지 URL을 제공하고, 준비 중 이미지인 메뉴에만 placeholder를 표시한다. 날짜 캐시는 모든 메뉴가 준비될 때까지 `WAITING` 상태를 유지하며 웰스토리 재확인을 계속한다.
